# 指标方法论与设计取舍

改动指标口径前先读本文。这里记录每个设计决定的原因，以及踩过的坑。

## 1. 数据来源

| 项目 | 内容 |
|---|---|
| 接口 | `https://edith.xiaohongshu.com/api/sns/web/v1/search/recommend?keyword=<词>` |
| 触发方式 | 在搜索框键入文本后由前端自动发起，返回 `data.sug_items[]`（通常 10 条） |
| 是否需登录 | 否。未登录可正常返回联想词 |
| 排序含义 | 列表顺序按热度相关性排序，第 1 条是该输入下最强的搜索意图 |

因为接口带 `x-s` / `x-t` 签名，纯 HTTP 无法复现，因此用 Playwright 驱动真实 Chrome 模拟键入，从网络响应中截获结果，而不是逆向签名。

## 2. 为什么用「联想排序」当热度代理

拿不到官方搜索量时，可用的免费信号只有三个：

1. **联想列表中的名次** —— 小红书按搜索热度排序，名次越靠前需求越强
2. **命中广度** —— 同一个词能在多少个不同输入下被联想出来，反映语义中心度
3. **是否为核心联想** —— 完整输入种子词时出现的词，最贴近真实搜索意图

搜索结果页的笔记互动量本是最好的信号，但**未登录会被风控硬拦**，实测三条路都走不通：

- PC 端 `/search_result?keyword=` → 302 到登录页，`error_code=300012`
- 加 `source=web_explore_feed` → 同样被拦
- 移动端 UA 访问 → 返回「你访问的页面不见了」

因此放弃内容侧指标，退到联想排序。

## 3. 联想热度 heat

```
排名分 pos  = mean( 1 - (rank - 1) / 10 )        # 第1名=1.0, 第10名=0.1
命中置信度 conf = 0.6 + 0.4 × min(occ, 5) / 5    # 出现1次=0.68, 5次以上=1.0
heat = 100 × pos × conf
```

- `occ` 是该词在多少个场景下被返回（`prefix_hits` 与 `l1_lists` 合计）
- 加入置信度是因为「只出现一次」的信号不稳定，不应与「五次都命中且都靠前」同分
- 早期版本曾把 `occ` 作为独立权重项（55% 名次 + 45% 广度），结果大量只出现一次的词挤在 A 档，区分度差，改为置信度乘子

## 4. 相关度 rel 与噪音问题

**这是最重要的一节。** 联想接口对短词、英文词会产生大量拼音或前缀噪音：

| 种子词 | 噪音示例 |
|---|---|
| muse | 木薯、木薯糖水怎么煮、沐森堂沐浴露、慕苏美容仪 |
| codex | cod乙女系列、cod壁纸、cod拼豆图纸（"使命召唤"） |
| Claude | cla系lolita、clamp卡游、clannad头像、clarins双萃精华 |
| 工作台 | 工商银行秋招笔试、工藤新一、工厂 |

麻烦在于：这些噪音词会**在自己的小圈子里互相联想**。例如「木薯」下面会出现「木薯桃胶炖奶」，后者又命中多个场景，热度分被抬到 72 分，一度挤进 S 档。

第一版修正用「前缀长度占比」加权，失败：`workb`（占 workbuddy 的 62%）会把真正相关的「workbuddy保姆级教程」压下去，而 `mu`（占 muse 的 50%）压不住噪音。

第二版改为**以「词里是否包含种子词」为语义锚点**，有效且可解释：

```
若 word 包含种子词          -> 0.95
若来自前缀联想且不含种子词  -> 0.60
若来自二级联想             -> 父词相关度 × 0.9（递归衰减，深度上限 5）
```

效果：
- `workbuddy新手入门教程`（含 workbuddy）→ 0.95，稳居 S
- `沐森堂沐浴露`（不含 muse）→ 0.60，从 S 掉到 C
- `木薯糖水怎么煮`（父词是木薯，木薯 0.60）→ 0.54，掉到 D

局限：中文近义词会被误伤。例如种子「教师」时，「教资面试」不含「教师」二字，只得 0.60，但它其实高度相关。这是当前口径的已知代价——宁可错杀噪音，也不让噪音污染头部。

## 5. 综合推荐分与梯队

```
score = heat × rel
```

梯队按 `score` 的**分位数**在同批词内分层，而非固定阈值：

| 梯队 | 分位 |
|---|---|
| S | 前 5% |
| A | 5% ~ 20% |
| B | 20% ~ 50% |
| C | 50% ~ 80% |
| D | 其余 |

额外规则：S 档要求 `occ ≥ 2`，只命中一次的词最高只能到 A（避免单点信号冒充强词）。

为什么用分位数而非固定分数：词量从 900 涨到 1700 时，固定阈值会导致 S 档只剩 10 个或暴涨到 90 个，分位数能保证梯队始终是有意义的相对分层。代价是**不同批次之间的梯队不可直接比较**，词库规模变化后需重算。

## 6. 已知局限

1. **不是搜索量**。热度只反映联想网络的活跃度，与真实月搜索量正相关但非线性。头部大词和长尾词在各自场景里都能排第 1，分数接近，但量级可能差几十倍。
2. **场景不可比**。「教师资格证」联想列表里的第 10 名，和「工」联想列表里的第 10 名不是一回事，但公式给同样分数。这是分位数分层的根本原因，也是跨场景对比不可靠的原因。
3. **无时效性**。联想结果随热点变化，数据是采集那一刻的快照，没有趋势维度。要趋势需多次采集对比。
4. **限 10 条**。接口单次最多返回约 10 条，看不到第 11 名之后的长尾。

## 7. 需要权威数据时

登录聚光平台（`ad.xiaohongshu.com`）→ 工具 → **关键词规划工具**，可查月搜索量、竞价激烈程度、建议出价。需要广告账户且开通搜索推广。

千帆（`ark.xiaohongshu.com`）是电商商家后台，搜索词只覆盖自家店铺进店词，不适合全站词查询。

拿到官方数据后，可把月搜索量作为新列并入明细表，与本表的相对热度交叉验证——通常头部词的排序会高度一致，差异大的词值得人工复核。
