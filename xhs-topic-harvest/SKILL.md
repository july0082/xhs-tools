# 小红书话题采集与数据包

从红书创作平台发布页的「# 话题联想下拉」批量读取话题名与浏览量，沉淀为可分析的数据包。全链路为：**唤起编辑器 → 逐词采集 → 合并去重 → 建表出包**。

## 何时使用

- 用户给一批关键词，要采集每个词下面的关联话题及其浏览量
- 需要把采集结果做成话题数据包 / 词库 / 选题优先级表
- 已有历史采集 CSV，需要合并、去重、重出数据包
- 需要按「标签库」固定表头（id/name/views/size/...）导出导入文件

不适用：需要小红书全站话题库（发布页每词上限 50 条）、需要笔记数/互动数据（联想下拉不提供）、需要免登录运行（必须登录态）。

## 前置检查（每次开始前逐条确认）

1. **CDP 通道**：请求 `http://127.0.0.1:9222/json/version` 有响应才继续；无响应走第 2 步。
2. **浏览器生命周期（最容易踩的坑）**：本机执行环境会在**命令结束时回收该命令派生的所有子进程**，`chrome.exe` 也一样——`cmd start`、`spawn detached`、`unref` 都撑不过一次工具调用。因此：
   - **默认用 `scripts/run.mjs`，把「启动 → prepare → crawl」放在同一条命令里**，一次跑完
   - 需要用户中途登录时，先用一条**后台任务**把浏览器撑住（`chrome ... --remote-debugging-port=9222 ... ; sleep 900`），登录完成后再在后续调用里跑 prepare / crawl；后台任务结束后浏览器会一起退出，属正常
3. **登录态**：首次在一台机器上跑一定需要登录。`run.mjs` 检测到未登录（`NOT_LOGGED_IN`，或发布页找不到上传入口）时会自动进入等待：在屏幕上打印「需要登录」提示，并每 6 秒重试一次，最长等 `--login-wait`（默认 360 秒）。让用户在弹出的 Chrome 窗口里登录即可，登录成功后程序自动继续采集，不需要重跑命令。登录态保存在 `--profile` 目录，通常可复用数周。
   - 等待期间不要结束这条命令，否则浏览器会被回收。告知用户：**用专门采集的小号登录，不要用主号**。
4. **运行环境**：Node ≥ 18（内置 fetch/WebSocket，无需装依赖）；`build.py` 需要 openpyxl。

## 工作流

### 第 1 步：一条命令采集（推荐）

```bash
# 启动浏览器 + 唤起编辑器 + 采集，全部在一次调用内完成
node scripts/run.mjs --seeds "kimi,通义千问" --depth 1 --out ./out
# 首次使用指定配置目录（保留登录态）
node scripts/run.mjs --seeds "..." --depth 1 --out ./out --profile "D:\xhs-profile"
```

退出码：`0` 成功 / `2` 需登录但等待超时（登录后再跑同一条命令即可） / `3` 端口超时或找不到上传入口 / `4` 编辑器未出现。

`run.mjs` 内部顺序：复用或启动 Chrome（等端口就绪）→ `prepare.mjs` 唤起 `.ProseMirror` → `crawl.mjs` 采集。

### 第 2 步（可选）：浏览器已常驻时，分开跑

若用户自己开着一个调试浏览器（窗口一直在），可跳过启动，直接：

```bash
node scripts/prepare.mjs     # 输出 EDITOR_READY 才继续
node scripts/crawl.mjs --seeds "..." --depth 1 --out ./out
```

采集参数说明：

- `--depth 1` 只采种子词（每词约 5 秒）；`--depth 2` 再展开一层（每词 50 个关联词）
- `--depth 3` 必须配 `--min-views 10000000`，只展开大话题
- 已采过的词自动跳过（读 `--out` 目录下所有 CSV 建索引），可安全重跑续采
- 每词间隔 1.2~2.5 秒随机；每 20 词休息 25~45 秒
- 出现「滑动验证/操作过于频繁/账号异常」立即停止
- 急停：在 `--out` 的上一级建 `STOP` 空文件，下一词前退出，已采数据保留
- 逐条 append 写 CSV，中断不丢数据
- 每词 ≤50 条是平台硬上限，已实测滚到底无更多加载

### 第 3 步：建表出包

```bash
python scripts/build.py --input ./out --xlsx ./小红书话题数据包.xlsx --csv ./小红书话题总表.csv --taglib ./标签库导入.csv --seeds "kimi,通义千问"
```

种子词本身是人名、品牌或短英文词时，先跑一遍，看选题表 Top 20 有没有撞词，再用 `--noise` 排除：

```bash
python scripts/build.py --input ./out ... --noise "八喜|乔任梁|antonelli"
```

`--noise` 可重复传入，命中即标「噪声(联想误匹配)」，不进选题与蓝海表。

- `--input` 可以是目录（读其中所有 CSV）或单个/多个 CSV
- 自动识别两种表头：`源关键词,话题名,浏览量,浏览量原文,采集时间`（首轮）与 `层级,父关键词,话题名,浏览量,浏览量原文,采集时间`（递归轮）
- 输出 5 个 sheet：总览 / 话题明细 / 关键词汇总 / 选题优先级 / 蓝海机会
- `--taglib` 生成标签库 13 列：`id,name,views,size,created_at,used,heat,use_count,avg_likes,category,source,topic_id,views_at`
- 派生列写成静态值（非公式），避免无公式引擎时预览空白

### 第 4 步：交付与说明

交付时固定说明四件事：

1. 每词 50 条上限，不是抓漏
2. 相关性分档清洗（相关 / 偏离·家具装修 / 偏离·语义无关 / 噪声·联想误匹配），选题与蓝海只统计「相关」；但**清洗规则只覆盖已知品类**，种子词若是短英文词、人名、品牌名，务必提醒用户抽查 Top 20 —— 撞词通常就在高浏览量段（见 `references/pitfalls.md` 第 9 条）
3. 数据是采集时点快照
4. 每轮会留一条本地草稿（存浏览器本地，不进用户账号），可忽略


## 输出字段与判定规则

- `references/dom.md`：DOM 结构、选择器、浏览量解析规则
- `references/pitfalls.md`：已知坑（粘行、大小写误并、同名词、频控）

赛道归类、量级分层、噪声判定的正则与阈值集中在 `scripts/build.py` 顶部常量区，调整时改常量，不要改函数体。

## 常见故障

| 现象 | 处置 |
|---|---|
| `ws connect failed` / 端口无响应 | 浏览器没起来或已退出，重新拉起并保持窗口 |
| `NOT_LOGGED_IN` | 请用户扫码，二维码过期则刷新页面 |
| 采集全是 0 条 | 编辑器未就绪或下拉未渲染，先跑 `prepare.mjs`，再按 `references/dom.md` 校验选择器 |
| 导入标签库报"列对不上" | 用 `--taglib` 产物；仍失败则让用户导出样本，按样本对齐日期格式与字段语义 |
| CSV 首行与上一行粘连 | 追加前确认文件以换行结尾（见 pitfalls） |
